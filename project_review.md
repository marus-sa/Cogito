# Проверка Cogito перед публикацией и защитой

Дата: 23 октября 2026 года. Проверяется версия исходников для ветки `codex/account-sessions-release`, не опубликованный сайт. Этот файл — техническая сверка и список оставшихся задач, а не оценка комиссии и не итоговый отчёт.

## Аккаунты

| Роль | Получение доступа | Границы доступа |
| --- | --- | --- |
| Ученик | Регистрация и подтверждение почты | Свои занятия, задания и цели |
| Родитель | Регистрация и подтверждение почты | Учебные данные только связанных с ним детей |
| Репетитор | Подтверждение почты и одобрение администратором | Свои занятия, задания и отчёты |
| Наставник | Администратор назначает роль подтверждённому аккаунту | Данные и отчёты закреплённых репетиторов |
| Администратор | Первый аккаунт создаётся при настройке; последующие назначаются действующим администратором | Заявки, участники, роли, связи и общие показатели |

На странице входа роль не выбирается. Сервер определяет её по записи пользователя. Переданный клиентом параметр `role` при входе не даёт дополнительных прав. При обычной регистрации административные роли запрещены.

Для назначения наставника или второго администратора человек сначала регистрирует обычный аккаунт и подтверждает почту. Глава проекта меняет роль в «Участниках». Это назначение существующего аккаунта, а не автоматическая рассылка приглашений. Пароль знает только его владелец.

Каждый вход создаёт независимую сессию в общей базе. Выход завершает только текущую сессию. Блокировка и смена роли завершают все сессии участника; разблокировка старые сессии не восстанавливает. При смене роли прежние связи родителя/ребёнка и наставника/репетитора снимаются. Себя нельзя заблокировать или лишить административной роли.

Родственные связи проверяет администратор перед назначением. Написанное пользователем имя ребёнка не является основанием для доступа. После снятия связи сервер перестаёт возвращать соответствующие данные при следующем запросе; уже увиденную человеком информацию отозвать невозможно.

## Проверки и их границы

Команды: `npm run build`, `npm run test:client`, `npm run test:api`, `npm run test:accounts`. Серверные проверки используют временные SQLite-базы и не подключаются к `DATABASE_URL` работающего сайта.

23 октября 2026 года сборка, 7 клиентских модульных проверок, интеграционный сценарий API и 10 серверных проверок аккаунтов прошли успешно. GitHub Actions подготовлен локально; это не подтверждение его выполнения в GitHub.

Проверяется:

- пять ролей и отказ в административных действиях для остальных ролей;
- независимые сессии одного аккаунта, выход с одного устройства, общие данные профиля, сохранение сессий после повторной инициализации приложения;
- подтверждение почты с другого клиента, одноразовость ссылки и запрет входа без подтверждения;
- срок сессии, поведение «Запомнить меня», HTTP-only cookie и Secure в production;
- блокировка, смена роли, назначение и снятие связей, ограничения наставника;
- одновременное создание записей и возврат каждой записи своему запросу;
- очистка интерфейса при смене аккаунта и отклонение запоздалых ответов предыдущего аккаунта.

Для писем в тестах используется подмена отправителя. Это не проверка SMTP-доставки. Независимые тестовые клиенты моделируют разные устройства, но не заменяют проверку на настоящих телефонах и в разных браузерах. PostgreSQL и Docker на этом компьютере не запускались.

Матрица ручной приёмки опубликованной версии:

| Среда | Что проверить | Состояние |
| --- | --- | --- |
| Локальный встроенный браузер, 1280×720 | Вход администратора и родителя без выбора роли, «Участники», запрет административного раздела родителю | Проверено на тестовом запуске |
| Тот же браузер, 390×844 | Форма участника без горизонтальной прокрутки | Проверено; это эмуляция размера, не iPhone |
| Android / Chrome | Регистрация, письмо, вход, обновление страницы, выход | Требуется реальное устройство |
| iPhone / Safari | Те же действия, в том числе переход из почтового приложения | Требуется реальное устройство |
| Компьютер / Firefox или Edge | Одновременный вход с телефоном, общие данные, независимый выход | Требуется отдельный браузер |

## Материалы для защиты

По [действующей странице защиты](https://school.hse.ru/nis/defenceproject) IT-продукт и видео демонстрации размещаются в GitHub, а итоговый отчёт отправляется в 2359. После отправки финальных материалов доработка не допускается. На выступление указано 10 минут, ориентир для презентации — около 12 слайдов; печатать загруженный отчёт не требуется.

Перед отправкой:

1. Сверить исходники GitHub, работающий адрес и окончательную заявку в 2359.
2. Подготовить отчёт: титульный лист, неизменённая окончательная заявка из 2359, описание продукта, рефлексия, виза заказчика или настоящие отзывы аудитории. Готовые компоненты и полученную помощь описать отдельно от личного вклада автора.
3. Проверить оформление по [общей инструкции 2025 года](https://school.hse.ru/data/2025/11/06/136109421/%D0%98%D1%82%D0%BE%D0%B3%D0%BE%D0%B2%D1%8B%D0%B9%20%D0%BE%D1%82%D1%87%D1%91%D1%82%20%D0%B8%20%D0%BF%D1%80%D0%BE%D0%B4%D1%83%D0%BA%D1%82%20-%20%D0%B2%D1%81%D0%B5%20%D0%BF%D1%80%D0%BE%D0%B5%D0%BA%D1%82%D1%8B%202025.docx): Times New Roman 14, интервал 1,5, поля 2 см, выравнивание по ширине, отступ 1 см; имя файла латиницей, размер до 15 МБ.
4. Записать скринкаст с голосом, показывающий все актуальные сценарии на демонстрационных аккаунтах. Не показывать пароли, токены, почту и переписку реальных участников. Проверить звук и доступность ссылки.
5. Подготовить презентацию и локальную резервную копию демонстрации на случай недоступности хостинга.

Связанная со страницей IT-инструкция датирована 2020 годом и содержит исторические даты, онлайн-формат и требование печати. Эти пункты нельзя автоматически переносить на 2026 год. Актуальные сроки и противоречия нужно уточнить в 2359 и у эксперта.

## Что блокирует готовность публичной версии

- Исправления готовятся в отдельной ветке. Старая версия сайта не получает их до выпуска.
- 23 октября в кабинете Render подтверждено: бесплатная PostgreSQL приостановлена после истечения срока, до удаления данных указано 4 дня. Владелец выбрал новую бесплатную базу Neon и повторную регистрацию пользователей вместо платного восстановления старой базы. Старая база не удалялась. Подключение новой базы и доступность сайта ещё нужно подтвердить.
- Нужны действующие PostgreSQL, `DATABASE_URL` и резервное копирование. SQLite на временном диске хостинга не подходит для постоянных аккаунтов.
- Для новых регистраций нужны SMTP-настройки и корректный HTTPS `APP_URL`. Без доставки письма подтверждение почты не завершится. Реальные секреты вводятся только в настройках хостинга.
- Render Free блокирует SMTP на 25/465/587. Нужен отправитель, поддерживающий другой разрешённый порт с TLS (например, 2525), либо HTTPS API. Поддержка SMTP в исходниках сама по себе не доказывает отправку на бесплатном хостинге.
- Нужны проверка опубликованной версии на двух реальных устройствах, отзыв заказчика/аудитории, диаграммы, отчёт, видео и презентация.
- Самостоятельное восстановление пароля обычного пользователя, нагрузочные испытания и политика обработки данных остаются отдельными задачами. Наличие кнопки согласия не заменяет политику.
