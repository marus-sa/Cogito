# Cogito · Light Hearts

Рабочее веб-приложение для учеников, родителей, репетиторов, наставников и администрации. Интерфейс сделан на Vue, сервер — на Python/Flask. Данные хранятся в SQLite локально или PostgreSQL на хостинге.

## Что лежит в проекте

- `src` — интерфейс сайта: страницы, кнопки и оформление;
- `server` — сервер, вход, роли, чаты и база данных;
- `Dockerfile` и `docker-compose.yml` — запуск одной командой;
- `render.yaml` — настройка публикации на Render.

## Как разобраться в коде

Лучше начать с одного действия — создания занятия. Оно проходит через пять мест:

```text
src/views/ScheduleView.vue     форма и кнопка «Создать занятие»
          ↓
src/stores/lessons.js          addLesson() отправляет данные
          ↓
src/api.js                    обычный fetch к /api/lessons
          ↓
server/app.py                 lesson_list() проверяет роль и выполняет INSERT
          ↓
server/database.py            connect_db() открывает базу данных
```

Сервер возвращает созданную запись. `addLesson()` добавляет её в список, Vue показывает её на странице. Остальные действия устроены так же.

Порядок чтения:

1. `src/main.js` — запуск сайта и восстановление входа по cookie.
2. `src/router/index.js` — какая страница открывается по адресу.
3. `src/config.js` — названия ролей, меню и разделы поиска.
4. Одна страница из `src/views` — её форма, кнопки и обработчики.
5. Соответствующий файл в `src/stores` — списки данных и запросы.
6. Нужный маршрут в `server/app.py` — обработка запроса и SQL.
7. `server/database.py` — таблицы и подключение к базе.

В каждом `.vue`-файле три части: `<script setup>` — переменные и действия, `<template>` — разметка, `<style scoped>` — оформление этой страницы.

Основные обозначения Vue: `ref` хранит одно изменяемое значение, `reactive` — объект с полями формы, `computed` — вычисляемое значение. `v-model` связывает поле с переменной, `@click` вызывает функцию при нажатии, `v-if` показывает блок по условию, `v-for` выводит список.

В `src/helpers.js` находятся короткие общие функции, например подсчёт минут. `src/components` содержит повторяющиеся элементы: кнопку, окно, аватар и карточку показателя. Добавлять новые слои для обычной формы не нужно.

На сервере `GET` читает записи, `POST` создаёт, `PATCH` меняет часть записи, `PUT` сохраняет профиль. SQL-запросы написаны прямо в обработчиках. `@need_login` проверяет вход, `role_error()` — роль. Проверки паролей и одноразовых ссылок используются из стандартных библиотек; писать свои алгоритмы шифрования не требуется.

## Запуск через Docker

1. Скопируйте `.env.example` в `.env`.
2. Задайте `POSTGRES_PASSWORD`, а для первого запуска — `ADMIN_EMAIL` и `ADMIN_BOOTSTRAP_PASSWORD` (от 12 символов).
3. Выполните:

```bash
docker compose up --build
```

Сайт откроется по адресу `http://localhost:5000`.

Compose дождётся готовности PostgreSQL и запустит приложение. Войти можно с почтой и паролем администратора из `.env`. Для писем подтверждения заполните в том же файле SMTP-настройки и пересоздайте контейнер приложения. Обычный `.env` не попадает в Git и в образ Docker.

## Запуск без Docker

Нужны Node.js 20+ и Python 3.10+.

```bash
cd server
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
./.venv/bin/python app.py
```

Во втором терминале:

```bash
npm install
npm run dev
```

Vite покажет адрес сайта в терминале. При первом запуске пустой локальной базы создайте администратора на странице `/setup-admin`. Эта страница доступна только на локальном запуске. Без `DATABASE_URL` сервер сам создаёт SQLite-базу в `server/data`.

## Проверка после изменений

```bash
npm run build
npm run test:api
npm run test:accounts
npm run test:client
```

Команды собирают интерфейс, проверяют API, все роли с независимыми сессиями и смену аккаунта в интерфейсе. Серверные проверки работают на временных базах. Реальные аккаунты они не меняют. Такой же набор проверок и сборка Docker подготовлены в `.github/workflows/check.yml`.

## Аккаунты и устройства

На любом устройстве входите по одной почте и паролю: роль берётся из базы автоматически. Для этого устройства должны открывать один опубликованный HTTPS-адрес с общей PostgreSQL-базой, а не каждый свой `127.0.0.1`.

В «Участниках» администратор назначает роли подтверждённым аккаунтам, блокирует доступ и настраивает связи родителя с ребёнком и наставника с репетитором. Служебная роль назначается уже зарегистрированному человеку, а не выбирается при регистрации. Выход завершает только текущую сессию; блокировка или смена роли — все сессии этого пользователя. Встроенная инструкция находится в разделе «Помощь».

## Почему выбран такой стек

Vue обновляет формы и списки без ручного переписывания HTML. Pinia хранит общие данные нескольких страниц, Vue Router связывает их с адресами. Flask позволяет держать простые обработчики HTTP и обычные SQL-запросы рядом. SQLite удобен для локального запуска без отдельного сервера базы, PostgreSQL — для общей постоянной базы опубликованного приложения. Интерфейс и API работают на одном адресе, поэтому не нужны отдельный сервер авторизации, JWT и настройка междоменных запросов.

## Публикация

`render.yaml` создаёт только веб-сервис на Render. Для постоянных аккаунтов задайте `DATABASE_URL` внешней PostgreSQL, например Neon Free. Бесплатная база самого Render истекает через 30 дней и не подходит для постоянного использования. Исключение её из Blueprint не удаляет существующую базу.

В Render вручную задаются `DATABASE_URL`, `ADMIN_EMAIL`, `ADMIN_BOOTSTRAP_PASSWORD`, `APP_URL` и настройки отправителя из `.env.example`. Адрес `APP_URL` должен совпадать с HTTPS-адресом сайта. Секреты не добавляются в GitHub. Новая пустая база не содержит аккаунтов старой: для переноса нужна резервная копия или доступ к прежней базе.

Render Free блокирует исходящие SMTP-порты 25, 465 и 587. Обычный SMTP Gmail/Yandex на них не заработает. Текущий код поддерживает STARTTLS на другом порту, например 2525, если его поддерживает ваш почтовый провайдер. Перед открытием регистрации проверьте настоящее письмо и переход по ссылке. Сведения об ограничениях: [Render Free](https://render.com/docs/free), [Neon Free](https://neon.com/pricing), [пример провайдера с портом 2525](https://help.brevo.com/hc/en-us/articles/10905415650322-Which-SMTP-port-should-I-use-Port-587-465-or-2525).
